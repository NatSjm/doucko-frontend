# Design — implement-platform-foundation-ui

## Goals / Non-goals

Goals: the UI checks later slices extend, and FR-58. Non-goals: a router
library (the first slice with a second route, admin-access, picks one), any
API call, any feature screen.

## Screens and states

Only the app shell: the product name as the page heading. It is the single
entry in `src/app/routes.tsx`. `App` renders the route registered for
`location.pathname`, wrapped in `data-route="<path>"` (`display: contents`)
so the e2e checks prove they reached that screen; any other path shows a
not-found screen. `document.title` comes from the catalog; `index.html`
keeps the same name as the pre-load title, and a unit test keeps the two equal.

## Design-system mapping

The shell uses the design system's tokens and type classes (`dk-t-title`).
Theme: `tokens.css` already switches on `prefers-color-scheme` unless
`<html data-theme>` is set. The app never sets `data-theme`, so the OS
decides (FR-58), and no component offers a toggle.

## Data flow

None yet. The generated client (`src/api/generated/schema.d.ts`) is
regenerated by `typecheck` and `build` from the pinned contract (NFR-12), and
a Vitest check confirms that every contract path is in it.

## Copy

- `src/i18n/cs.ts` is the child catalog (Czech). `src/i18n/en.ts` is the
  admin catalog (English). Both are typed, and a missing key is a type error.
- `useT()` reads the catalog from `I18nProvider`. Tests render `App` with a
  pseudo-catalog (every value wrapped `⟦…⟧`) and require every text node,
  text attribute (`aria-*` names and descriptions, `title`, `alt`,
  `placeholder`, visible input values) and `document.title` under
  `document.body` to consist only of whole wrapped segments, so a literal
  concatenated to catalog text is caught too (NFR-9).
- Lint rule `doucko/no-literal-ui-text` is a local ESLint rule with no new
  dependency. It reports a string with a letter that can reach the screen or
  the accessibility tree: JSX text; literals inside child expressions
  (conditional, logical, template, `+`); the same in DOM text attributes;
  and the same in any prop of a component except identifier/styling props
  (`NON_TEXT_PROPS`, `name` on `Icon`/`ChoiceGroup`); literals nested in arrays,
  objects (except identifier keys such as `value`), template expressions, TS
  wrappers, `String('…')` and method calls on a literal; and a literal assigned
  to `document.title` in `.ts` and `.tsx`. Unit tests lint probe files through
  `eslint.config.js` to prove the wiring. Tests, the catalogs, the vendored
  design system and generated code are exempt. It cannot follow a variable or
  another module; the pseudo-catalog render is the backstop there.
- Known gap (out of scope here): components in the vendored design system
  carry default Czech strings (e.g. `AnswerPart` placeholder, `Feedback`
  labels). The design system is linted nowhere, so feature slices must pass
  every text prop from `t()`; the fix belongs in the design-system artifact.

## Accessibility

- `e2e/a11y.spec.ts`: axe-core (`wcag2a`, `wcag2aa`) on every route in
  `routes.tsx`, in light and in dark, in every browser project. It fails on
  any serious or critical violation (NFR-13). This puts the a11y check in
  the `test:e2e` battery. The installed `check:a11y` script stays available
  as the standalone runner.
- Reduced motion: `components.css` already honours `prefers-reduced-motion`.
  The e2e checks every route after network idle and again 500 ms later,
  counting running and pending animations with a duration.

## Provenance (NFR-4, CA-D21)

`fixtures/PROVENANCE.md` lists every file under `fixtures/`, `e2e/fixtures/`,
`evals/cases/` and the asset roots (`public/`, `src/assets/`,
`src/design-system/fonts`, `src/design-system/icons`), and every image,
font, audio, video, PDF, office or plain-text data file anywhere in git, and
JSON/Markdown/YAML data under `src/` (outside the design system) and `e2e/`.
Only `contract/` and the recordings a `docs/qa/**/manifest.json` lists are
exempt. Open (harness, recordings slice): `scripts/record-demos.mjs` does not
run the real-name guard yet; it must before the first recording is committed. Fixtures must be `self-authored`. A
skin asset may also be `licensed: <SPDX>` with its licence file (same
origin and author) listed beside it (the two OFL fonts).

## PII (NFR-3)

- `e2e/fixtures/profile.ts` exports the fictional display name the stack is
  seeded with for e2e runs and recordings.
- `expectNoRealName(page)` fails if the text of a page contains the value
  of `DOUCKO_CHILD_DISPLAY_NAME`, the real name set on the laptop. It never
  hands the name to a matcher, so a failure (and the QA report that copies
  it) does not contain it. Against a stack (`E2E_BASE_URL`) the variable is
  required. `e2e/fixtures/test.ts` runs it after every test as an auto
  fixture; every spec imports `test` from there.

## Serving (Dockerfile, nginx)

- Base images pinned by digest (node 22, nginx stable 1.30). The build stops
  if `contract/api/openapi.yaml` is missing, so the image is always built
  from the pinned contract (NFR-12).
- nginx: one origin for SPA and `/api/` (proxied with the original
  `Host`, and `X-Forwarded-For` overwritten with `$remote_addr` so a client
  cannot spoof its address to the login throttle; the backend's copies of
  the server-level security headers are hidden); `backend` is re-resolved through Docker's
  DNS (`resolver 127.0.0.11`, variable `proxy_pass`), so a recreated backend
  is found and nginx starts before it; a missing `/assets/` file is 404, not
  the SPA page; the shell is sent with `expires -1`; `server_tokens off`; `X-Content-Type-Options`,
  `Referrer-Policy` and a CSP (`script-src 'self'`, `frame-ancestors
  'none'`, `object-src 'none'`) on every response. nginx still runs as
  root inside the container; an unprivileged image would change the
  Compose port mapping and is left to Phase 5. `client_max_body_size 51m`
  follows NFR-17's 50 MB upload cap; the CSP allows inline styles because
  React `style` props need them (scripts stay `'self'`).
- DNS rebinding: a `default_server` answers 421; the app server only answers
  `localhost` and bare IPv4 hosts (127.0.0.1, the LAN address). `/api`
  without the slash is 404. The backend no longer publishes 8080 (only this
  image's 8081 is published), and its own firewall refuses any other host
  with 400 too (backend `SecurityConfiguration.httpFirewall`).
- Live check: `npm run test:container` (`tools/container-smoke.mjs`) builds
  the image, runs it beside a stub backend on a private network and checks
  the proxying, headers, fallback, 404s and the Host guard over HTTP, then
  runs the Playwright suite through nginx (`E2E_BASE_URL`). That last step
  needs `DOUCKO_CHILD_DISPLAY_NAME` (env or `../backend/.env`) for the
  real-name guard; without it the step is reported NOT RUN and the command
  fails. Each run writes `docs/qa/container-smoke-latest.md`.
- The security headers and `server_tokens off` sit at http level (before the
  servers), so the 421 refusal carries them too; no server or location
  declares its own `add_header`.
- Recordings exempt from provenance are exactly `results[].video` (.webm)
  and `results[].screenshot` (.png) of a `docs/qa/**/manifest.json`.
- Screens: the a11y and theme e2e iterate `e2e/screens.ts`: every registered
  route plus the not-found screen, each with its `data-route` marker.
  `routePath` maps `/index.html` and a trailing slash to the registered path.
  The no-toggle e2e clicks every control (a failed click fails), waits for
  async effects, and is skipped (never passed) on a screen with no control;
  `src/app/theme-source.test.ts` holds app code (outside the design system)
  and `index.html` to three invariants: no CSS custom property declared or
  set anywhere, no colour-scheme API, and no string literal naming a scheme
  (`dark`, `light`, `theme…`; catalogs excepted).
- `tsconfig.e2e.json` gives only the e2e specs DOM types; Node-side config
  files have none.

## Accepted limits (review round 3)

Kept on purpose; each later slice covers what it adds.

- NFR-9 is two layers, neither complete: the lint rule sees only literals in
  the file (not through variables, other modules or `createElement`), and
  the pseudo-catalog render sees only what the registered routes show once
  settled. Interaction states (loading, error, dialogs) belong to the
  slice that adds them, whose tests render them with the pseudo-catalog.
- Provenance is by file type and location: workbook content committed as a
  TS/JS module or in an archive outside the fixture roots is not detected.
  Review and the "never commit" rule cover it.
- `client_max_body_size 51m` applies to every `/api/` path; the backend caps
  child request bodies at 16 KB (NFR-17), so nginx only bounds the transfer.
- `.dockerignore` mirrors the repository's `.gitignore`, not a developer's
  `.git/info/exclude` or global excludes: a file hidden only there reaches
  the image without making the smoke's tree dirty. The evidence also names
  the image id, which is exact.
- The real-name guard reads the page's `innerText`; attributes and titles
  are covered by the pseudo-catalog (no name is in a catalog).

## Risks & mitigations

- Firefox and Edge must be installed for the browser projects. Playwright
  installs Firefox, and Edge comes with Windows. A missing browser fails
  loudly, never as a skip.
- No router yet, so `routes.tsx` is a plain array that slice 2 adapts to the
  chosen router (an ADR in this repo).
